## 最初の実 API 実験（Phase 1）へ進む条件（案）

利用者と ChatGPT が判断するための案です。決定ではありません。

1. **承認**：利用者が、実験の目的・回数・上限額（例：以前の計画にある 3 ドル）を明示して承認する。
2. **公式情報の確認**：使うモデルの ID、料金、構造化出力（JSON Schema strict）に対応しているかを、OpenAI の公式ドキュメントでその時点に確認し、`[pricing]` に出典と確認日を入れる。
3. **管理画面側の上限**：OpenAI の組織またはプロジェクトの使用量上限を、コード側の上限より低い額に設定する【未確認：現在の設定項目は OpenAI の画面で確かめる】。
4. **キーの保管**：専用プロジェクトのキーを `.env`（Git の管理外）か環境変数に置き、`civlab check-config` で `blockers` が空になることを確かめる。
5. **小さく始める**：まず住民 1〜2 人×1〜2 ターン（有料呼び出しは数回）で、`max_paid_calls`、`max_estimated_cost_usd`、`--stop-file` を設定して実行する。
6. **事後確認**：`civlab summary` の推定コストと、OpenAI の管理画面での実際の使用量を照らし合わせ、差を記録する。
7. **検証**：`civlab verify` で世界の更新を再生検証する（判断の区分は B でも、世界の更新は A）。

## 次の段階の作業候補（優先順の案）

1. OpenAI アダプターの実接続での動作確認（上記の条件をすべて満たしてから）
2. 実験条件のセット（シナリオ）の管理：dev と heldout を別ファイルに分け、`scenario_hash` で突き合わせる
3. 複数シードでの一括実行と、要約統計（平均・ばらつき）
4. AI 教師インターフェースの雛形：実行ログを入力にして、プロンプト案（新しい版）を出力する。採用するかは人が判断する
5. 世界の拡張：出来事、関係性、資源の種類（World Engine の規則を版で管理する）
6. gitleaks など外部の秘密情報検査ツールの追加（案。自作スクリプトとの二重化）
7. main のブランチ保護の設定（[security.md](security.md) の推奨。利用者の承認後に行う）

## 既知の制約

- Mock の住民はルールで動くだけで、知的な判断のモデルではありません。
- `estimate_input_tokens` は文字数 ÷ 2 の多めの見積りです。実際のトークン数は API の報告値で記録します。
- Bash の permission ルールは、安全の境界ではありません（公式ドキュメントのとおり）。
